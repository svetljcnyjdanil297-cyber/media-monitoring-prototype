# Прототип системы медиамониторинга

## 1. Цель проекта

Разработать прототип системы сбора и первичной обработки публикаций из разных интернет-источников. Система должна сохранять тексты и метаданные, приводить их к единому формату, выявлять повторяющиеся материалы и классифицировать публикации по темам и предварительной тональности.

## 2. Источники данных

В рамках прототипа исследованы шесть источников:

| Источник | Результат |
|---|---|
| 5 Колесо (LiveJournal) | Собрано 10 публикаций |
| iRecommend | Собрано 10 отзывов |
| 4PDA | Собрано 10 тем форума |
| Drive2 | Собрано 10 публикаций |
| Отзовик | Получен 1 тестовый отзыв; массовый сбор ограничен |
| Дзен — компьютеры | Автоматический сбор не завершён из-за перенаправления на страницу авторизации |

Таким образом, сформирован набор из 41 записи. Из них четыре источника представлены десятью записями каждый, ещё один — одним тестовым отзывом. Для Дзена автоматическая выгрузка не получена.

## 3. Архитектура

Обработка данных организована по последовательным этапам:

1. **Сбор.** Отдельные скрипты получают публикации и отзывы из выбранных источников.
2. **Сохранение.** Исходные результаты сохраняются в формате JSON.
3. **Нормализация.** Поля приводятся к единой структуре: источник, ссылка, заголовок, текст, автор, дата и рейтинг.
4. **Дедупликация.** Повторные ссылки исключаются, а публикации с одинаковым содержимым помечаются как дубликаты.
5. **Классификация.** Публикациям назначаются тематические метки, сохраняются совпавшие ключевые слова и определяется предварительная тональность.
6. **Формирование результатов.** Сводные данные сохраняются в JSON и CSV для дальнейшего анализа.

## 4. Результаты обработки

На текущем наборе данных:

- Собрано и нормализовано 41 запись.
- Обнаружен 1 повторный материал с одинаковым текстом, но другой ссылкой и датой публикации.
- Для аналитики учитываются 40 уникальных по содержимому материалов.
- Реализована многометочная классификация по тематическим категориям.
- Выполнена предварительная оценка тональности.

Количество тематических совпадений после исключения повторного содержимого из статистики:

| Категория | Совпадений |
|---|---:|
| Потребительский опыт | 20 |
| Технологии и ПО | 20 |
| Автомобили и транспорт | 19 |
| Туризм и путешествия | 14 |
| Финансы и банки | 12 |

Предварительная оценка тональности 40 уникальных материалов:

| Тональность | Количество |
|---|---:|
| Отрицательная | 13 |
| Положительная | 12 |
| Нейтральная или не определена | 15 |

Одна публикация может относиться к нескольким темам, поэтому сумма тематических совпадений не равна числу публикаций.

## 5. Файлы результатов

- `data/normalized_articles.json` — нормализованный набор публикаций.
- `data/normalized_articles.csv` — таблица, которую можно открыть в Excel.
- `data/source_summary.json` — сводка по состоянию источников.
- `data/classified_articles.json` — записи с тематическими метками и оценкой тональности.
- `data/classification_summary.json` — агрегированная статистика классификации.

## 6. Как запустить обработку

Команды выполняются в терминале из корневой папки проекта при активном виртуальном окружении Python.

Сначала объединить данные:

```bash
python normalize_sources.py
```

Затем выполнить классификацию:

```bash
python classify_articles.py
```

Скрипты обработки используют встроенные возможности Python. Для сбора данных применяются дополнительные библиотеки и браузерная автоматизация в зависимости от конкретного источника.

## 7. Ограничения прототипа

1. Автоматический сбор пока работает не для всех источников.
2. Доступность страниц зависит от ограничений сайтов, перенаправлений и механизмов защиты от автоматических запросов.
3. Классификация основана на ключевых словах и не учитывает контекст в полной мере.
4. Оценка тональности носит эвристический характер и не является результатом обученной модели.

Перед промышленным использованием необходимо проверить качество классификации на размеченной выборке и обработать ошибки извлечения данных.

## 8. Дальнейшее развитие

Для масштабирования решения до тысяч источников предлагается:

- выделить единый интерфейс сборщика для подключения новых источников;
- использовать планировщик для регулярного обновления данных;
- добавить очередь задач, ограничение частоты запросов и повторные попытки при сбоях;
- перейти от набора JSON-файлов к централизованной базе данных;
- внедрить контроль качества данных и мониторинг состояния источников;
- улучшить классификацию и тональность с помощью лингвистических методов или обучаемых моделей;
- добавить поиск упоминаний брендов, динамику обсуждений и автоматические уведомления.

Масштабирование до 10 000 источников является направлением дальнейшего развития, а не уже реализованной возможностью данного прототипа.
